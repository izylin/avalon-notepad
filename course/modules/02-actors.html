Meet the Cast

Nine files, each with exactly one job. Know who does what, and you'll know exactly where to point an AI coding tool.

An orchestra, not a solo act

Think of this codebase like an orchestra. game.tsis the sheet music — the rules every player must follow, written down once and never broken. page.tsx is the conductor, holding the current state like a baton and cueing every section. Everything else is an instrument section: it plays its part and nothing more.

🎻
Why this matters for steering AI

When you ask an AI tool to "add a rule that a rejected vote skips the leader," you want it editing the sheet music (game.ts), not improvising inside a random instrument's part. Knowing the cast means you can say exactly that.

What the rulebook actually knows

A big tell that a component is "just an instrument section" and not the rulebook: it never invents game math on its own. Here's a real example — how many Loyal Servants and Minions a game needs, straight from game.ts:

CODE 
export function togglesFor(playerCount: number): Record<RoleKey, boolean> {
  const cfg = defaultConfig[playerCount];
  return roleKeys.reduce((acc, key) => {
    acc[key] = cfg.specials.includes(key);
    return acc;
  }, {} as Record<RoleKey, boolean>);
}
PLAIN ENGLISH

Given how many people are playing, figure out which special roles are on by default.

Look up the official rules for that player count (5 to 10 players each have a fixed table).

Walk through every possible role (Merlin, Percival, Morgana...)

and mark it "on" only if that player count's official setup includes it.

Hand back a checklist: one true/false per role.

Nowhere in SeatSvg.tsxor any other component will you find quest-size tables or role counts — they only ever display what game.ts decides.
