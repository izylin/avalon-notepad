# 0. 先看懂：一个网站是怎么工作的

这一章不要求你写代码。目标是先建立一张地图：以后看到“Node.js、数据库、Next.js、部署、Actions”时，知道它们分别解决什么问题。

## 从访问一个网址开始

当你在浏览器输入网址，大致会发生这些事情：

```text
你在浏览器输入网址
        ↓
浏览器向托管平台请求网页
        ↓
平台返回 HTML、CSS 和 JavaScript
        ↓
浏览器把文件组合成你看到和操作的页面
```

- **HTML** 决定页面有什么，例如标题、按钮和输入框。
- **CSS** 决定页面长什么样，例如颜色、间距和排版。
- **JavaScript** 决定页面会做什么，例如点击按钮后切换任务。
- **浏览器** 是网页的运行环境，也是用户真正使用产品的地方。

阿瓦隆笔记本的大部分游戏交互都在浏览器里完成，所以它看起来像应用，但底层仍然是网页。

## 前端和后端是什么

**前端**是用户能看到和操作的部分，例如任务页、投票结果和座位图。前端代码最终会在浏览器里运行。

**后端**是在服务器上运行、用户通常看不到的部分。它常用来：

- 验证账号和密码
- 保存所有用户共同使用的数据
- 保护不能公开的密钥
- 调用第三方服务
- 执行不应该交给浏览器的业务规则

这个项目的核心游戏流程不依赖后端。对局记录主要保存在每位用户自己的浏览器中，因此换设备或清除浏览器数据后，记录不会自动跟随。

## 服务器有什么用

服务器可以理解成一台一直联网、等待请求的电脑。用户发来请求，服务器处理后返回结果。

例如，如果未来要做“所有玩家加入同一个房间”，就需要服务器协调不同玩家的状态；只靠每个人各自的浏览器，大家看不到同一份实时数据。

静态网站不一定需要长期运行的应用服务器。GitHub Pages 会直接保存并发送已经做好的网页文件，这也是它简单、稳定的原因。

## Node.js 有什么用

JavaScript 最初主要在浏览器中运行。**Node.js** 让 JavaScript 也能在电脑或服务器上运行。

在这个项目中，Node.js 主要用于开发和构建：

```text
npm install   安装项目依赖
npm run dev   启动本地开发环境
npm run build 检查并生成可发布版本
```

Node.js 不等于网站，也不等于服务器；它是一种运行 JavaScript 工具和服务端程序的环境。

## 数据库有什么用

数据库用来长期、有结构地保存和查询数据。例如：

- 用户账号
- 多设备同步的对局记录
- 房间和玩家状态
- 所有人可见的排行榜
- 用户提交的反馈

可以把浏览器的 `localStorage` 想成“放在自己桌上的便签”，数据库则像“有目录和权限管理的公共档案室”。

阿瓦隆笔记本目前不需要数据库就能完成核心功能，这是一个重要的产品取舍：部署更简单，但数据不能天然跨设备或多人共享。

## React 和 Next.js 有什么用

**React** 帮助开发者把界面拆成可以组合和复用的组件。例如任务翻页器、身份标签面板和投票结果图都可以是独立组件。

**Next.js** 是建立在 React 之上的应用框架，它提供项目结构、页面组织、开发服务器、构建优化，以及可选的服务端能力。

可以这样理解：

```text
JavaScript：编程语言
React：搭建交互界面的工具
Next.js：组织和发布 React 应用的整套框架
Node.js：在浏览器之外运行开发工具和服务端代码的环境
```

## 部署平台有什么用

“部署”就是把只能在开发者电脑上运行的内容，变成别人能通过网址访问的线上版本。

不同平台提供的能力不同：

| 平台 | 更像什么 | 适合什么 |
| --- | --- | --- |
| GitHub Pages | 静态文件托管 | 文档、课程、作品集、静态网页 |
| Vercel | 前端应用部署平台 | Next.js、预览部署、可选服务端功能 |
| GitHub | 代码仓库和协作平台 | 保存代码、版本历史、PR、Issues |

这套学习网站发布在 GitHub Pages；完整的阿瓦隆 Next.js 项目仍然可以由学习者 Fork 后部署到自己的 Vercel。两者不是重复，而是承担不同任务。

## GitHub Actions 有什么用

GitHub Actions 是 GitHub 提供的自动化执行环境。仓库中发生某个事件后，它会按照工作流文件自动执行任务。

这个学习网站的流程是：

```text
代码进入 main
    ↓
Actions 按 .github/workflows/deploy-pages.yml 执行
    ↓
整理首页、课程和文档文件
    ↓
上传到 GitHub Pages
    ↓
公开网址更新
```

Actions 也可以运行测试、检查代码格式、制作安装包或发布版本。它负责“自动做事”，Pages 负责“保存并提供网页”。

## 这个项目带学习者学会了什么

完成课程后，学习者实际练习了这些能力：

| 学习动作 | 学到的概念 | 能解决的问题 |
| --- | --- | --- |
| Fork 仓库 | 开源协作、代码所有权 | 在不影响原项目的情况下练习 |
| Clone 和本地运行 | 本地环境、Node.js、依赖 | 把 GitHub 上的代码跑到自己电脑上 |
| 阅读组件和修改界面 | React 组件、前端状态 | 理解功能如何对应到代码 |
| Commit 和 Push | Git 版本历史 | 保存修改并同步到远程仓库 |
| 提交 PR | 代码评审和协作流程 | 让改动被讨论、检查和合并 |
| 部署到 Vercel | 构建、环境变量、线上部署 | 把 Next.js 项目变成可访问的网址 |
| 使用 GitHub Pages | 静态托管 | 发布课程和项目文档 |
| 查看 Actions | 自动化工作流 | 判断部署是否运行、在哪一步失败 |
| 排查打不开的问题 | 分层排错 | 区分代码、构建、平台和网络问题 |

## 还没有覆盖什么

完成这个项目并不等于已经学完 Web 开发。以下内容适合以后继续学习：

- 登录和用户权限
- 数据库设计与多人共享数据
- 真正的后端 API
- 自动化测试
- 网络安全与密钥管理
- 域名、缓存和性能优化

你不需要一次学会所有名词。更实用的方法是：先知道每块拼图的位置，再在项目需要它时深入学习。
