# 会议决策时间线

本页将分散的飞书周会记录按时间合并，只保留对理解产品演变有帮助的内容。飞书任务卡的内部 ID 和重复附件未迁移。

## 2026-06-24：立项

- 明确痛点：纸笔难以更新、关联和快速记录信息。
- 团队希望在解决真实游戏问题的同时，学习搭建完整网站。
- 初步提出嫌疑概率、玩法先验、身份标签、按轮回溯、快捷记录、共享笔记和历史统计等方向。
- 确认 Linus 为 Product Owner，Yumi 为 Scrum Master，全员参与开发。

## 2026-06-28：确定核心流程与 MVP

- 首页先提供规则介绍。
- 创建游戏涉及人数、阵容、座位和首轮队长等设置。
- 游戏记录聚焦组队、投票和任务结果。
- 数据存储选择本地方案。
- 核心流程确认为：创建游戏 → 组队 → 全员表决 → 执行任务 → 累计结果 → 结束并回顾。
- 当时的会议图将“连续五次否决”描述为坏人直接获胜；后续测试文档曾采用“第五次强制出发”的不同口径，说明该规则在项目中经历过理解和实现调整。当前规则应以代码与 README 为准。

## 从会议记录看到的迭代路径

```text
真实痛点
  → 大量产品设想
  → 收敛 MVP 流程
  → 补齐规则与存档
  → 上线前收尾与测试安排
  → 重构交互
  → 加入导览、反馈和复盘
```

这体现了 User-Centred Design 与敏捷开发的结合：以用户在桌面上的真实记录行为为中心，通过可运行版本、观察和反馈不断调整，而不是在立项时一次决定所有细节。
